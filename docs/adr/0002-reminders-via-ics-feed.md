# Reminders se entregan vía calendar feed ICS, no push notifications

Los reminders de tareas con ETA y de hábitos diarios se sirven a través de un endpoint `/api/ical/{user_id}/{token}.ics` que el usuario suscribe una vez en su calendar app (Google/Apple) usando `webcal://` para tap-to-subscribe en iOS. Web Push (PWA) se descartó pese a ofrecer realtime y mejor UX inicial porque suma superficie de mantenimiento — service worker, VAPID keys, tabla de subscriptions, cron dispatcher, manejo de subs expiradas (HTTP 410), y la dependencia de un cron gratuito (Vercel Hobby 1/proyecto). ICS es un GET puro, sin estado mutable ni jobs; el calendar app del usuario maneja toda la UX (snooze, repeat, multi-device). El trade-off aceptado es la latencia de polling (horas) y el setup inicial tedioso, especialmente en Google Calendar mobile que no permite suscribir por URL. Si el feedback futuro pide realtime, Push se puede sumar sin remover ICS — no son excluyentes.
